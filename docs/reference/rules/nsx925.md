## What it checks

The identity `nsx test` runs as isn't allowed to use Databricks SQL.

## Why

Tests run as SQL on a warehouse, and a workspace only lets an identity use Databricks SQL once it has the `databricks-sql-access` entitlement. A service principal often lacks it, because deploying a bundle doesn't need it. It exits 2.

## Example

The Development Environment's deploying identity has no `databricks-sql-access` entitlement. In a project, this fails:

```console
$ nsx test --pr 42
```

## Fix

Ask a workspace admin to give the identity the `databricks-sql-access` entitlement, and `CAN USE` on the SQL warehouse Tests run on.
