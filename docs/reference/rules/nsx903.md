## What it checks

`NIMBLESTAX_DATABRICKS_CLI` names a Databricks CLI that Nimblestax can't run.

## Why

Nimblestax runs its own pinned Databricks CLI, which it downloads the first time it needs it. `NIMBLESTAX_DATABRICKS_CLI` points Nimblestax at a CLI you installed yourself instead, for a machine that can't download one. The file it names doesn't exist, or this machine can't run it.

## Example

`NIMBLESTAX_DATABRICKS_CLI` is set to `/opt/databricks/databricks`, which doesn't exist. In a project, this fails:

```console
$ nsx deploy --env dev
```

## Fix

Point `NIMBLESTAX_DATABRICKS_CLI` at the Databricks CLI's binary, or unset it so Nimblestax downloads its own.
