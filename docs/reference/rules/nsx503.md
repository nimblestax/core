## What it checks

The Environment's Deployment Manifest was written by a Nimblestax that didn't record how each table is made.

## Why

The Plan tells a new column from any other change by comparing each table's definition with the one the manifest recorded. A manifest from an earlier Nimblestax records only each table's type and file, so the Plan shows new tables and warns instead of guessing at the rest.

## Example

dev was last deployed by an earlier Nimblestax. In a project, this warns:

```console
$ nsx plan --env dev
```

## Fix

Deploy the Environment again with this Nimblestax, which records each table's definition. Until then, read each table's change in the pull request.

## Principle

This Rule enforces [Every change goes through a pull request, with a Plan a human reviews](https://nimblestax.com/way/every-change-goes-through-a-pull-request), from the Nimblestax Way.
