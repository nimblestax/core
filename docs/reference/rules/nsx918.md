## What it checks

A file in the Build Package `nsx deploy --package` was given differs from what was built.

## Why

Every Environment receives the same Build Package, so prod runs exactly what the stages before it ran. `nimblestax.package.json` holds a checksum of each file, and a file that was added, removed or edited since breaks that promise, so Nimblestax deploys nothing. The diagnostic names the files that differ.

## Example

`build/src/sales/gold/fct_orders.sql` was edited after `nsx compile`. In a project, this fails:

```console
$ nsx deploy --env dev --package build
```

## Fix

Deploy the package as `nsx compile` wrote it. To change what it holds, change the project and build a new one.
