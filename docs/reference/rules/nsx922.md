## What it checks

`nsx preview down` found a schema in the preview's bundle state outside your `u_<user>__` schemas, or outside the Development Environment's catalogs.

## Why

`nsx preview down` destroys what the preview's bundle deployed, read from its bundle state. A Preview Environment only ever has your own `u_<user>__` schemas in the Development Environment's catalogs, so anything else in that state is a mistake, and `nsx preview down` refuses to remove anything rather than drop it. It exits 2.

## Example

The preview's bundle state holds the schema `prod_sales.silver`. In a project, this fails:

```console
$ nsx preview down
```

## Fix

Find out how that schema got into the preview's bundle state before removing anything. Drop the preview's own schemas by hand if you need to.
