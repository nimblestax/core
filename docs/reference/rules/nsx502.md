## What it checks

The Environment the Plan compares with has no Deployment Manifest.

## Why

The Plan compares the project with what an Environment last received, which its Deployment Manifest records. Each successful deploy writes one, next to the deployed bundle in the deploying identity's folder. With none, every table looks new, so the Plan shows each one as a `create` and warns, because some may already exist. Signed in as anyone else, the Plan looks in that person's folder and finds none.

## Example

dev hasn't been deployed yet. In a project, this warns:

```console
$ nsx plan --env dev
```

## Fix

Nothing to do before the Environment's first deploy, which writes the manifest. Otherwise, run the Plan signed in as the identity that deploys the Environment, as the pull request workflow does.

## Principle

This Rule enforces [Every change goes through a pull request, with a Plan a human reviews](https://nimblestax.com/way/every-change-goes-through-a-pull-request), from the Nimblestax Way.
