## What it checks

`NIMBLESTAX_DATABRICKS_CLI` names a Databricks CLI older than this Nimblestax supports.

## Why

Each Nimblestax release is tested with one Databricks CLI version and names the oldest it supports. An older CLI can deploy the same project differently, so Nimblestax refuses it and runs nothing. A CLI that doesn't report its version is refused too.

## Example

`NIMBLESTAX_DATABRICKS_CLI` names a Databricks CLI at version 0.240.0. In a project, this fails:

```console
$ nsx deploy --env dev
```

## Fix

Point `NIMBLESTAX_DATABRICKS_CLI` at the Databricks CLI version the diagnostic names, or unset it so Nimblestax downloads its own.
