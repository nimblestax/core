## What it checks

SQL reads a table by the Logical Name another Naming Style would give it, not the project's.

## Why

A Logical Name is the table's real name without the Environment, so its shape follows the Naming Style: `silver.sales.orders` under `layer-catalogs`, `sales.silver.orders` under `system-and-domain-catalogs` and `sales_silver.orders` under `environment-catalogs`. A name in another style's shape is what you'd query in another project, not this one. It's most often left behind when the style changes before the first deploy.

## Example

Write this file into the project `nsx init` creates, and `nsx validate` fails:

`domains/sales/models/gold/fct_orders.sql`:

```sql
SELECT order_id, amount
FROM silver.sales.orders
```

## Fix

Write the table as the diagnostic says: its Logical Name in the project's Naming Style.

## Principle

This Rule enforces [Code names tables logically; Nimblestax resolves the environment](https://nimblestax.com/way/code-names-tables-logically), from the Nimblestax Way.
