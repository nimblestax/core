## What it checks

A table changed in a way this version of the Plan doesn't class yet.

## Why

The Plan classes each change as safe, refresh or destructive, so a reviewer knows where to look. This version classes new tables and new columns. Any other change to a table, such as a changed filter, a changed or dropped column, a changed Source or a removed table, is reported with this warning instead of a guessed class, so it is never shown as safe when it might not be. The Plan still succeeds.

## Example

dev's Deployment Manifest holds `fct_orders` as `nsx init` writes it. In a project, this warns:

```console
$ nsx plan --env dev
```

## Fix

Read the change to the table's config or SQL in the pull request before you approve it.

## Principle

This Rule enforces [Every change goes through a pull request, with a Plan a human reviews](https://nimblestax.com/way/every-change-goes-through-a-pull-request), from the Nimblestax Way.
